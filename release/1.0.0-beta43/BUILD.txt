OPPower 1.0.0-beta43 构建说明
================================

本版聚焦快充：控制策略的功率稳定性，以及快充页"看得见"的反馈。
没有改任何界面骨架，也没有新增依赖。

一、升功率改为逐档回升（ChargingController）
--------------------------------------------
上一版之前，温度回落时规则表直接把目标从当前档跳到该温度段档位，一次可能跨
3～4 档。功率瞬间翻倍，几十秒后电池又冲回 43°C 被降档，形成几十秒一轮的锯齿，
用户体感是"功率在跳"。

现在 confirmGear 对"升功率"（requested < current，gear 数字变小）做单步限幅：
每次最多一档，每档走一次确认时间（temperatureUpshiftSeconds，默认 8 秒）。

- 降功率不限幅：跨多档也一次到位，保护温度优先。
- 改基础档位走 controlSettingsChanged 分支，仍然立即生效，不受限幅影响。
- 达到 MAX_OUTPUT 时目标恒为 gear 0，限幅自然不会介入。
- 限幅生效时状态消息标注「逐档回升」，避免用户误以为卡住。

二、快充页新增「当前充电」组
----------------------------
拆页之后快充页只剩一行实时功率，看不出"这次到底充了多少"。新组自下而上：

  实时功率（保留全页唯一的大字号）
  充电器      协议 · 当前用到 xx%      65 W
  本次充入    32% → 61%               1234 mAh
  本次时长                             42 分钟
  平均 / 峰值功率             38.2 / 54.1 W

数据全部来自主页记录同源的 ChargeRecord 和 ChargeInsight.capability，
不新增任何 Binder 调用与采样。未接电时显示一行「接电后开始统计」。

三、「当前策略」行加档位诊断
----------------------------
系统实际档位 = 热控基础档 + cosa 偏移，OPPower 只能改 cosa。三个数任何一个对不上，
功率都不会变。现在摘要直接给出：

  基础档 8 · cosa -3 · 计算档 5 · 目标 2

原来要进设置页点「读取档位」才能看到，排查"功率没上来"多绕一步。

四、文案校正
------------
- 高功率保活：明确「开启后由系统保活通道接替档位控制」，即 cosa 不再写入；
  80% 或充满后暂停（默认 socStopPercent=80，与实现一致）。
- 电流上限：明确「手动值优先于档位折算，可以高于档位基准」。这是既有行为
  （manualValueWinsOverGear 测试锁定），原文案容易让人以为上限只会往下压。
- 自动调节说明：补「升温降档一次到位、回温逐档回升」。

仍需真机复验
------------
1. 温度回落时功率是否逐档爬升（约 8 秒一档），而不是一下跳回最高。
2. 升温降档是否仍然一次到位，没有被延迟。
3. 快充页「当前充电」的时长与充入是否随采样增长；拔电后是否显示"接电后开始统计"。
4. 充电器利用率是否与检测页一致。
5. 「当前策略」摘要里的三个档位数字，是否与实际功率变化对得上。

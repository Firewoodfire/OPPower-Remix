这一版修什么
------------
点「充电记录 / 放电记录」必闪退。

根因不在记录弹窗本身，而是整个应用从来没有提供**窗口级背景源**。
COUI 的 Dialog 在创建 Dialog 窗口时执行：

  val windowBackdrop = backdrop ?: LocalCouiMenuBackdrop.current
  if (material != null) checkNotNull(windowBackdrop) { "弹窗项目材质需要宿主提供..." }

Dialog 默认带材质（玻璃底），所以这里必然抛 IllegalArgumentException。
崩溃发生在 `ComposeDialog(...)` 内部，也就是弹窗窗口创建的瞬间。

为什么"只有记录会崩"看着像功能 bug
----------------------------------
首启那个「关于 OPPower」弹窗也走同一个 Dialog，照理也一样崩。它不崩的原因是：
它只在你清数据后第一次打开时出现，那一次崩溃被系统吞成"闪退"，之后再也没人复现。
记录弹窗能随时点，所以问题全暴露在它身上。

修法
----
在应用根部包一层窗口级背景源（`provideCouiMenuBackdrop`，公开 API）：

  ProvideCouiMenuBackdrop { contentModifier ->
      PageTransition(
          target = page,
          depthOf = { it.depth },
          label = "RootPage",
          modifier = contentModifier.fillMaxSize(),
      ) { current -> ... }
  }

注意 `CouiBackdrop` 的构造函数是 internal，应用层只能通过
`rememberCouiBackdrop()` / `ProvideCouiMenuBackdrop` 这类公开入口拿。这一层
只提供一次，所有弹窗（记录、恢复默认确认、清空记录确认、首启说明）共用同一份源。

顺带修的一处
------------
记录弹窗里最多列 20 条历史（`HISTORY_IN_DIALOG`），标题会写明"最多显示 20 条"。
原来 `records.asReversed().forEach` 是无上限的：历史攒到几百条时，弹窗首帧要一次性
测量几百个卡片。弹窗本身已有 `heightIn(max = 460dp) + verticalScroll` 兜底，
限条数只是避免点开那一帧卡顿。

排查过程中排除的假设
--------------------
- 不是 `Clickable` 砸到非零最小约束：`CouiCard` 是 `fillMaxWidth`，行是
  `padding + Row`，不会拿到 Constraints(minWidth>0, minHeight=0)。
- 不是 `verticalScroll` 在无界高度下测量：COUI 的 dialog action 区是
  `Column(if (naturalHeight > constraints.maxHeight) Modifier.verticalScroll(...))`，
  这写法本身就说明 `constraints.maxHeight` 是有限的。
- 不是记录数据为 null：`selected == null` 分支已经在。

  1. 点「充电记录」：弹窗能否正常弹出、有没有玻璃底
  2. 点「放电记录」：同上
  3. 弹窗里的历史卡片点一下：能否切换上方详情

  5. 设置页的「恢复默认」「清空记录」确认弹窗：是否正常
